# Этапы разработки MVP (чек-листы)

Как пользоваться:
- Порядок: A → 1 → 2 → 3 → 4 → 5 → 6. Следующий этап начинается, когда пройдены «ворота» (gate) предыдущего. **Исключение: этап 0 (исследование бэкенда) можно вести параллельно этапу 1**, потому что каркас использует заглушки (`AuthConfig`, `BackendProfile`). Ворота этапа 0 обязательны до начала этапа 2. Для этапа 1 из этапа A нужны пункты A.1-A.4 (SDK, JDK, git, Codex); Context7 (A.5-A.7) агенту нужен тоже, лучше подключить сразу. Serena снята 2026-09-26.
- Пункт отмечаем `[x]` только после проверки способом из раздела «Как проверить».
- В конце этапа: коммит и тег `stage-N-done`, отметка в файле этапа.
- Для Codex: перед каждым этапом даём стартовый промпт из блока этапа. Он просит сначала план, а потом код.
- **Работаем по TDD** (правила: `AGENTS.md` и [architecture/testing.md](../architecture/testing.md)): для каждого пункта с логикой сначала тест-лист, красный тест, потом код. В этапах 1-5 ниже есть «тест-лист» с тем, что пишется первым. Этапы A и 0 без TDD (окружение и исследование).
- Пункт с логикой не отмечается `[x]`, пока не показан цикл «красный → зелёный».

## Обзор

| Этап | Что должно быть по итогу | Ворота |
|---|---|---|
| [A. Окружение](a-environment.md) | Всё установлено, Codex видит Context7, репозиторий готов | `codex mcp list` показывает оба сервера |
| [0. Проверка](0-spike.md) | Заметка с проверенными константами и решением GO/NO-GO по способу входа | Решение записано в `docs/backend-notes.md` |
| [1. Каркас](1-skeleton.md) | Скелет модулей по [architecture/overview.md](../architecture/overview.md), порты и фейки, чат работает на фейковой модели, границы защищены тестами | Запуск на устройстве, `./gradlew check` зелёный, защита реально срабатывает |
| [2. Авторизация](2-auth.md) | Вход, хранение и обновление токена, выход | Токен обновляется сам, в логах его нет |
| [3. Клиент модели](3-model-client.md) | Настоящий диалог со стримингом | Ответ идёт потоком, «Стоп» работает |
| [4. Инструменты](4-tools.md) | Будильник, уведомление, поиск файлов + цикл агента | Три сценария из ТЗ проходят на телефоне |
| [5. Обвязка](5-hardening.md) | Ошибки, история, настройки, устойчивость | 10 негативных сценариев проходят |
| [6. Замеры и APK](6-release.md) | Замеры энергии/памяти, подписанный APK, инструкция | Все критерии приёмки из [ТЗ](../product/overview.md) |
