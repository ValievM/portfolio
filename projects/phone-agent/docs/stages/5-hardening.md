# Этап 5. Обвязка и устойчивость

> Читать перед началом: [требования](../product/requirements.md) · [компоненты](../design/components.md) · [Design QA](../design/qa.md) · [тесты и TDD](../architecture/testing.md)

**Цель:** приложение не ломается на неидеальных сценариях.

- [x] 5.1 История чата в Room, кнопка «Очистить». Хранение: `RoomConversationRepository` + `ConversationDao` (`observe()`/`replace()`), покрыто `RoomConversationRepositoryTest` и тестами `ChatViewModel` (восстановление после перезапуска, очистка, отправка во время очистки, внешняя очистка отменяет активный ход и не даёт ему восстановить историю — `external empty history emission cancels active turn and clears chat`, `completed/failed cancelled turn cannot restore history after external clear`). Кнопка «Очистить» — только на экране настроек, с диалогом подтверждения; из TopAppBar чата убрана. Живой перезапуск на телефоне — строка в `manual-verification.md`.
- [x] 5.2 Экран настроек: способ входа и статус, папка для поиска, модель, выход. Покрыто тестами: `SettingsViewModelTest` (выбор модели, реальный способ входа из `SessionAuthCoordinator`, выход, SAF-папка, очистка истории), `PreferencesSettingsRepositoryTest` (модель, `searchFolderUri`, значения по умолчанию), `OkHttpModelCatalogTest` (оба формата `/models`, отказ). Живая проверка входа/выхода/SAF-папки на телефоне — `manual-verification.md`.
- [x] 5.3 Единый обработчик ошибок и тексты в `strings.xml`. Один исчерпывающий `when` без `else` — `ErrorPresentation.kt` (`ErrorPresentationTest`): новый `AgentError` не скомпилируется без сообщения; сырые причины на экран не попадают. Повтор запроса — `ChatUiEvent.Retry` (`ChatViewModelRetryTest`).
- [ ] 5.4 Поворот экрана и смерть процесса во время стрима не теряют историю и не падают. Код и unit-тесты готовы: вопрос сохраняется сразу при отправке (виден после перезапуска); при старте с «висящим» вопросом без ответа показывается инлайн-ошибка `Interrupted` с «Повторить» (`ChatViewModelProcessDeathTest`); собственные сохранения не перестраивают ленту (`fix/chat-own-emission-order`); черновик композера переживает пересоздание активити (`ChatComposerDraftUiTest`, `StateRestorationTester`). «Стоп» в любой момент (даже сразу после отправки) не теряет вопрос — следующий submit и перезапуск видят оба вопроса; неожиданное исключение в ходе не роняет приложение, а показывает ошибку с «Повторить»; устаревшая ошибка сохранения стирается успешным сохранением; завершённый ход сохраняет вопрос ровно один раз (`ChatViewModelProcessDeathTest`, сценарии с неконфлейтящим репозиторием как у Room). **Частично**: частичный текст ответа, уже показанный на экране, не восстанавливается (в истории его нет — вместо него `Interrupted` с «Повторить»); живая смерть процесса (во время стрима и во время выполнения инструмента) и поворот на реальном телефоне — `manual-verification.md`.
- [x] 5.5 Логи без токенов и содержимого чата с данными файлов (проверка). Аудит и найденные исправления — [log-audit.md](../log-audit.md); правило «сообщение лога — константа» и «нет `android.util.Log`» закреплены в `ArchitectureTest`.
- [ ] 5.6 R8/ProGuard правила для `kotlinx.serialization` и Room, release-сборка запускается. R8 включён (`app/build.gradle.kts`, `proguard-android-optimize.txt` + `app/proguard-rules.pro`); правила только адресные: подавлены предупреждения OkHttp об опциональных TLS-провайдерах, которых нет на Android (BouncyCastle JSSE/Conscrypt/OpenJSSE — из официальной инструкции OkHttp); `kotlinx.serialization`, Room и Hilt приносят свои consumer-правила сами. Сборка: `assembleRelease` зелёный, APK 11,5 → 3,1 МБ, `mapping.txt` сохраняется для дебэкраншотов; `testReleaseUnitTest` зелёный (74 теста, UiTest/screenshot исключены по-прежнему). `shrinkResources` выключен до живой проверки. **Частично**: запуск минифицированного APK на телефоне не проверялся — строка в `manual-verification.md`; подпись APK — этап 6.
- [ ] 5.7 Состояния по [design/components.md](../design/components.md): пустой чат с подсказками, баннеры «нет сети» и «сессия истекла», инлайн-ошибка с «Повторить». Код и тесты готовы (`EmptyState`, `StatusBanner`, `InlineError`, `ChatScreenStatesUiTest`, снимки); живая проверка на телефоне — в `manual-verification.md`. Отличие от описания: у баннера «сессия истекла» нет кнопки «Войти заново» — при истёкшей сессии `MainActivity` сам показывает экран входа.
- [ ] 5.8 Design QA (чек-лист [design/qa.md](../design/qa.md)) пройден для всех экранов; скриншот-тесты (Roborazzi) для `Composer`, `ToolCallCard` (все состояния), `ApprovalSheet`, `AssistantMessage`; эталоны записаны после утверждения дизайна. Скриншот-тесты готовы (`app/src/test/.../screenshot/`: `Composer`, `ToolCallCard` все состояния, `ApprovalSheet`, сообщения и экран целиком, светлая/тёмная тема и шрифт 2.0); в `check` идут как smoke (без картинок), `recordRoborazziDebug`/`verifyRoborazziDebug` пишут и сверяют эталоны. **Частично**: эталоны не записаны и не закоммичены — сознательно, до утверждения дизайна пользователем (`design/qa.md`); Design QA на реальном телефоне не пройден (`manual-verification.md`); после `stage-3/assistant-markdown` ассистентские сообщения рендерятся маркдауном — их скриншоты нужно обновить после утверждения.**Тест-лист (пишем первым):**
- Для каждого из 10 негативных сценариев, где это возможно, сначала тест на уровне `AgentLoop`/`ChatViewModel` с фейками: какое состояние и какое сообщение ожидаем. Только потом реализация.
- Room: чтение-запись истории; `Opaque`-элементы сохраняются без потерь; миграции.
- Сценарии, которые по TDD не проверить (убийство процесса, занятый порт 1455, отзыв доступа к папке): ручной чек-лист или instrumented-тест, результат записан в отчёте этапа.

**Что должно быть по итогу:** приложение ведёт себя предсказуемо в плохих условиях.

**Как проверить — 10 негативных сценариев (все должны пройти без падения):**
1. Режим полёта во время ответа.
2. Обрыв сети на середине стрима.
3. Истёкший access-токен.
4. Отозванный/невалидный refresh (`invalid_grant`).
5. 403 от бэкенда.
6. 429 (лимиты).
7. Порт 1455 занят при входе.
8. Отказ в разрешении на уведомления.
9. Папка для поиска удалена или доступ отозван.
10. Приложение убито во время выполнения инструмента.

**Ворота:** все 10 сценариев проходят, `lint` без критичных замечаний.

**Стартовый промпт:** «Работаем над этапом 5. Составь таблицу «сценарий → ожидаемое поведение → как воспроизвести» для 10 негативных сценариев из этого файла и покажи мне, потом реализуем.»
