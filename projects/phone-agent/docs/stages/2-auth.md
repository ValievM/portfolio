# Этап 2. Авторизация

> Читать перед началом: [требования](../product/requirements.md) · [адаптеры](../architecture/adapters.md) · [тесты и TDD](../architecture/testing.md) · [проверенные значения входа](../backend-notes.md)

**Цель:** пользователь входит, токен хранится безопасно и обновляется сам.

- [x] 2.1 Интерфейс `AuthProvider` и модель состояния (`SignedOut`, `SigningIn`, `SignedIn`, `Error`).
- [x] 2.2 `TokenStore`: DataStore + AES-GCM, ключ в Android Keystore (не `EncryptedSharedPreferences`).
- [x] 2.3 PKCE: генерация `code_verifier` и `code_challenge` (S256), `state`; unit-тесты.
- [x] 2.4 `ChatGptBrowserAuth`: Custom Tab + приёмник на `127.0.0.1:1455`, проверка `state`, обмен кода на токены, закрытие приёмника, таймаут.
- [x] 2.5 `ChatGptDeviceCodeAuth`: показ кода, опрос по `interval`, лимит 15 минут; подсказка про переключатель Device code authorization.
- [x] 2.6 `ApiKeyAuth`: ввод ключа, проверка тестовым запросом, хранение.
- [x] 2.7 Разбор JWT: `exp`, `chatgpt_account_id`; unit-тесты.
- [x] 2.8 Обновление токена: за ~30 с до `exp` и один раз после 401; под `Mutex`; новый refresh-токен пишется атомарно; unit-тест «10 параллельных вызовов → один refresh».
- [x] 2.9 Выход: токены удалены из хранилища.
- [x] 2.10 Экран входа и «Войти заново» при `invalid_grant`.

**Тест-лист (пишем первым):**
- PKCE: `code_verifier` 43-128 символов допустимого алфавита; `code_challenge` совпадает с эталонным вектором из RFC 7636, приложение B; `state` каждый раз новый.
- Редирект: неверный `state` → отказ; нет `code` → ошибка; истёк таймаут → ошибка без зависания.
- JWT: достаёт `exp` и `chatgpt_account_id` из всех трёх мест, где он может лежать; битый токен → ошибка как значение, не исключение.
- Обновление токена: истёк → refresh; осталось больше 30 с → без refresh; 10 параллельных вызовов → один refresh; новый refresh-токен сохранён раньше, чем выдан access; `invalid_grant` → состояние «войти заново».
- `AuthProvider`-ы: переходы состояний `SignedOut → SigningIn → SignedIn / Error`; device code: опрос по `interval`, лимит 15 минут.
- `TokenStore` (на устройстве): запись → чтение → выход → пусто.

**Что должно быть по итогу:** можно войти любым из трёх способов, `CredentialsProvider.current()` всегда возвращает живой токен, состояние переживает перезапуск приложения.

**Как проверить:**
- Unit-тесты PKCE, JWT, refresh и Mutex зелёные.
- На телефоне: вход через браузер проходит; при занятом порту 1455 (открыт тестовый сокет) включается device code; ввод ключа работает.
- Искусственно «состарить» токен (подменить `exp`) → следующий запрос обновляет его сам.
- Убить приложение и открыть заново → остаёмся в системе.
- Выход → в DataStore пусто.
- `adb logcat | grep -i "token\|bearer"` не показывает значений токенов.

**Ворота:** все проверки выше пройдены на реальном телефоне.

**Стартовый промпт:** «Работаем над этапом 2. Используй Context7 для DataStore и Android Keystore, значения входа бери из docs/backend-notes.md. Сначала план по пунктам 2.1-2.10. Токены никогда не логировать.»
