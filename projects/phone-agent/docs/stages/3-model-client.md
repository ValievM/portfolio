# Этап 3. Клиент модели

> Читать перед началом: [требования](../product/requirements.md) · [адаптеры](../architecture/adapters.md) · [ядро](../architecture/core.md) · [компоненты](../design/components.md) · [правила вёрстки](../design/layout-rules.md) · [доступность и безопасность](../design/a11y-security.md)

**Цель:** настоящий диалог с моделью, ответ идёт потоком.

- [x] 3.1 `ResponsesGateway` (реализует `ModelGateway`): построение запроса (`instructions`, `input`, `store=false`, `stream=true`, `prompt_cache_key`/`session_id`), заголовки и URL из `BackendProfile`.
- [x] 3.2 SSE-парсер: дельты текста, `function_call`, завершение, события ошибок; unit-тесты на `spike/sample_sse.txt`.
- [x] 3.3 Маппинг ошибок: 401 → refresh и один повтор; 403, 429, сеть, таймаут → понятные сообщения; unit-тесты с фейковым сервером (`MockWebServer`).
- [x] 3.4 Стриминг в UI: текст появляется по мере прихода.
- [ ] 3.5 Кнопка «Стоп»: отменяет запрос. Кнопка подключена в `ChatComposer`: во время ответа показывает Stop и отправляет `ChatUiEvent.Stop`; поле ввода остаётся отключённым. Логика отмены корутины/HTTP-вызова покрыта тестами (`ChatViewModelTest`, `ResponsesGatewayTest`). Проверка на реальном телефоне ещё ожидает пользователя (см. `manual-verification.md`).
- [x] 3.6 Ограничение истории: целые ходы, мягкий лимит (самый новый ход входит всегда, старые — пока помещаются), обрезка вывода инструмента до 4 КБ.
- [x] 3.7 Имя модели берётся из конфига/настроек.
- [x] 3.8 `AssistantMarkdown` на `multiplatform-markdown-renderer` (`-m3`, `-code`), потоковый режим; **картинки выключены**, ссылки только через подтверждение с показом домена, HTML не рендерится. Обёртка `AssistantMarkdown` (единственное место, где вызывается библиотека, проверено Konsist-правилом), ссылки — `evaluateLink` + `LinkConfirmationSheet` (только https, домен берётся из разбора URL, а не из текста), картинки — no-op трансформер без Coil (правило Konsist), незакрытый блок кода закрывается только для показа (`closeUnclosedFence`, иначе библиотека теряет последнюю строку). Версия библиотеки 0.39.2, а не 0.43.0 — см. [design/libraries.md](../design/libraries.md).
- [ ] 3.9 Лента по [design/layout-rules.md](../design/layout-rules.md) и [design/components.md](../design/components.md): `reverseLayout`, «прилипание» к низу, чип «↓ к новым», индикатор ожидания до первого токена, композер с превращением «отправить ↔ стоп». Проверен порядок обхода TalkBack; если он неверный, используем обычный порядок + логику прилипания. Логика «прилипания» — чистые функции `FeedFollow.kt` (`FeedFollowTest`), поведение ленты — `MessageListFollowUiTest` (Robolectric). Порядок обхода: сообщения читаются сверху вниз в хронологическом порядке, TalkBack идёт по геометрии — проверено на уровне семантики тестом; живой TalkBack и «на пальцах» на телефоне ждут пользователя (`manual-verification.md`); код и тесты готовы. Статус «Модель отвечает…» — `liveRegion = Polite`.

**Тест-лист (пишем первым):**
- Сборка запроса: `store = false`, `stream = true`, `instructions` не пуст; `function_call_output` использует тот же `call_id`.
- SSE-парсер на `spike/sample_sse.txt`: ожидаемая последовательность `TextDelta … Completed`; чанк, разорванный посередине события; неизвестное событие игнорируется; событие ошибки → `Failed`.
- Ошибки: 401 → refresh → один повтор; 401 дважды → `SessionExpired`; 403 → `Forbidden`; 429 → `RateLimited`; обрыв соединения → `Network`.
- Отмена: отмена корутины закрывает соединение (`MockWebServer` видит обрыв).
- `ContextWindowPolicy`: целые ходы, мягкий лимит — связанный вызов и результат никогда не разрезаются, окно начинается с вопроса пользователя; вывод инструмента обрезается ровно на границе 4 КБ.
- «Прилипание» к низу (чистая функция): пользователь внизу → автопрокрутка; прокрутил вверх → чип «↓ к новым» и никаких прыжков.
- `AssistantMarkdown` (превью + скриншот-тест): недозакрытый блок кода не ломает вёрстку; ссылка требует подтверждения с доменом; картинка не загружается.

**Что должно быть по итогу:** можно вести диалог с моделью на телефоне; контекст сохраняется между сообщениями; ошибки не роняют приложение.

**Как проверить:**
- Тесты парсера и ошибок зелёные.
- На телефоне: вопрос → ответ идёт кусками; второй вопрос учитывает первый.
- «Стоп» посреди ответа: сеть замолкает (видно в логах/профайлере).
- Режим полёта → понятное сообщение.
- Истёкший токен → тихое обновление и повтор.

**Ворота:** живой диалог на реальном телефоне + отмена работает.

**Стартовый промпт:** «Работаем над этапом 3. Формат запроса и события SSE бери из docs/backend-notes.md и spike/sample_sse.txt. Для OkHttp и корутин проверь актуальный API через Context7. Сначала план.»
