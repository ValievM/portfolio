# ADR 0003: поиск файлов через MediaStore

## Контекст

`find_files` ищет только внутри папки, которую пользователь заранее выбрал через SAF. Нужен отдельный быстрый поиск по доступному системному индексу, но Android scoped storage не предоставляет стороннему приложению полный индекс файлов. `MANAGE_EXTERNAL_STORAGE` запрещён требованиями MVP и не рассматривается как обход.

## Решение

Добавить `search_files` поверх MediaStore: запросить коллекции `Files` и `Downloads` по подстроке `DISPLAY_NAME`, сортировать по `DATE_MODIFIED DESC`, вернуть до 20 записей. Читать только метаданные: имя, URI для открытия, относительный путь, размер, дату изменения и MIME-тип. Дедуплицировать по точному имени и размеру, оставляя запись с самой свежей датой. Ограничить обход пятью секундами; содержимое файлов не открывать.

`search_files` работает только с теми строками MediaStore, к которым приложение получило доступ. На Android 10+ scoped storage ограничивает видимость файлов; гранулярные `READ_MEDIA_*` разрешения дают доступ к соответствующим типам медиа, а с Android 14 пользователь может разрешить доступ только к выбранным фото и видео через `READ_MEDIA_VISUAL_USER_SELECTED`. Загрузки, созданные другими приложениями, могут быть доступны только через SAF. Такой результат не является полным индексом всех файлов. Для поиска в выбранной папке по-прежнему предназначен `find_files`.

## Рассмотренные альтернативы

- `MANAGE_EXTERNAL_STORAGE`: отклонено — запрещено границами MVP и не подходит для публикации приложения в Google Play.
- Обход SAF-корней: отклонено — у приложения нет права обходить все корни. SAF используется только в существующем `find_files` внутри выбранной пользователем папки.

## Последствия

- Поиск возвращает доступные метаданные и `content://` URI; файл можно открыть отдельно после явного действия пользователя.
- Результаты могут быть неполными из-за выданного уровня доступа или ограничений Android. Недоступные загрузки не читаются через другой путь.
- Тонкий MediaStore-адаптер не тестируется обычными unit-тестами; в unit-тестах проверяются валидация, лимиты, нормализация, JSON-контракт и поведение при отказе в разрешении.
