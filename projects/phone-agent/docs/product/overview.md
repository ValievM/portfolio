## Цель
Нативное Android-приложение: пользователь скачивает APK, входит через аккаунт OpenAI и пишет в чат. Модель может выполнять действия на телефоне через узкие инструменты (tools). Без Termux, ADB и доп. установок.

## Границы MVP
**Входит:**
- чат с моделью (стриминг);
- вход через аккаунт OpenAI, запасной вход по API-ключу;
- 3 инструмента: будильник, поиск файлов в выбранной папке, уведомление;
- подтверждение пользователем перед действиями с последствиями;
- установочный APK.

**Не входит (позже):**
- управление чужими приложениями (тапы, скриншоты, AccessibilityService);
- чтение содержимого файлов, SMS, звонки, контакты;
- фоновая работа, расписания, foreground service;
- iOS, публикация в Google Play;
- Rust-ядро (только если замеры покажут необходимость).

## Стек
- Kotlin, Jetpack Compose, Material 3.
- minSdk 26, targetSdk — актуальная стабильная на момент старта (уточнить в Android Studio).
- Сеть: OkHttp (+ SSE-парсер, `okhttp-sse` или свой), kotlinx.serialization, корутины.
- Хранение: DataStore для токенов (значение шифруется AES-GCM, ключ в Keystore), Room для истории чата.
- Локальный HTTP-приёмник для OAuth: `ServerSocket` на `127.0.0.1:1455` внутри приложения.
- Сборка: Gradle, Android Studio (SDK, эмулятор, Logcat, Profiler). Код можно писать и в VS Code / через Codex CLI.

## Нефункциональные требования
- **Энергия:** нет фоновых сервисов, циклов и опроса; сеть только во время запроса; один общий `OkHttpClient`; отмена запроса при закрытии экрана/по кнопке «Стоп».
- **Память:** без тяжёлых библиотек, история ограничена, замер в Profiler. Целевые цифры уточнить после прототипа.
- **Безопасность:** токены в Keystore, в логах ни токенов, ни содержимого чата с данными файлов; только HTTPS; недоверенные данные не могут расширять список инструментов.
- **Устойчивость:** любые ошибки сети и авторизации приводят к понятному сообщению, а не к падению.
- **Прозрачность:** в настройках виден активный способ входа.
- **Процесс:** разработка по TDD (правила: `AGENTS.md` и [architecture/testing.md](../architecture/testing.md)). Новая логика пишется от красного теста.

## Критерии приёмки
- Установка APK и вход без дополнительных программ и настроек (основной путь).
- Если порт 1455 занят, срабатывает вход по device code; если нет доступа и к нему, работает ввод API-ключа.
- «Поставь будильник на 7:30»: шторка подтверждения → будильник виден в приложении Часы.
- «Найди файл X»: находит файлы только в выбранной папке, содержимое не читается.
- Искусственно «просроченный» access-токен обновляется сам, запрос не теряется; при `invalid_grant` показывается экран повторного входа.
- Модель не может вызвать ничего вне `ToolRegistry`; цикл останавливается после 5 шагов.
- Режим полёта и обрыв стрима дают понятное сообщение.
- После выхода токенов на устройстве нет, в логах их тоже нет.
- В простое приложение не появляется в топе расхода батареи.

## Риски и запасные варианты
| Риск | Что делаем |
|---|---|
| Закрытый бэкенд подписки: заголовки, формат и модели могут меняться, `originator` на 22.09.2026 не проверяется | Все константы в `BackendProfile`/`AuthConfig`; формат бэкенда изолирован в `:data:llm`; `ApiKeyAuth` обязателен; этап 0 как go/no-go |
| Ротация refresh-токена | Своя сессия на устройство, `Mutex` на refresh, атомарная запись |
| Сессия протухает после ~8 дней простоя | Экран «Войти заново», без падения |
| Redirect на `localhost:1455` не работает на каком-то устройстве | Device code (нужен включённый переключатель в настройках ChatGPT) или ключ |
| SAF медленный | Прямые запросы к `DocumentsContract`, лимиты глубины/количества/времени |
| Часы конкретного производителя игнорируют `SKIP_UI` | Результат «запрос отправлен», проверка в Часах; если игнорирует, показываем экран Часов без SKIP_UI |
| Prompt injection через названия файлов и уведомления | Только метаданные, подтверждения, жёсткий реестр инструментов, правила в `instructions` |

## Открытые вопросы
- Модель телефона и версия Android (влияет на minSdk и поведение Часов).
- Имя и иконка приложения (не должны выглядеть как официальное приложение OpenAI).
- Способ раздачи APK (GitHub Releases, прямая ссылка, F-Droid).
