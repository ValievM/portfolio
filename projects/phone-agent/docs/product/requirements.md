# Функциональные требования

> См. также: [обзор ТЗ](overview.md) · [ядро](../architecture/core.md) · [адаптеры](../architecture/adapters.md) · [компоненты интерфейса](../design/components.md)

## Авторизация
Способы входа — реализации `AuthProvider` (стратегия): `signIn()`. Токены, состояние (`AuthState`), обновление и выход ведёт `SessionManager`, который реализует `CredentialsProvider` (`current()`, `refreshAfterUnauthorized()`) и `signOut()`. Устройство: [architecture/adapters.md](../architecture/adapters.md).

Реализации:
1. **`ChatGptBrowserAuth` (основная).** PKCE в Custom Tab на `auth.openai.com`; приложение на время входа поднимает приёмник на `127.0.0.1:1455`, ловит `/auth/callback?code=...&state=...`, проверяет `state`, меняет код на токены, закрывает приёмник. Таймаут ожидания 3 мин. Пользователю не нужно ничего включать в настройках.
2. **`ChatGptDeviceCodeAuth` (запасная).** Если порт 1455 занят или редирект не сработал: показать код и кнопку «открыть auth.openai.com/device», опрашивать по `interval`, лимит 15 мин. В подсказке — про переключатель Device code authorization.
3. **`ApiKeyAuth` (обязательная в MVP, не «опциональная»).** Ввод ключа, проверка тестовым запросом, хранение в Keystore. Нужна как страховка, потому что эндпоинт подписки закрытый и не даёт гарантий стабильности.

Общие правила:
- Своя сессия на устройство: **не копировать `auth.json` с компьютера** (refresh-токены ротируются, копия ломает оба клиента).
- Обновление токена под `Mutex`: одновременных refresh быть не должно; новый refresh-токен записывается атомарно до использования.
- Обновлять за ~30 с до `exp` (из JWT) и один раз повторять запрос после 401.
- Токены только на устройстве, на свой сервер не отправляются. `allowBackup=false`, DataStore исключён из бэкапа.
- Ошибка `invalid_grant` или протухшая сессия → экран «Войти заново», без бесконечных повторов.
- Все константы (issuer, client_id, scope, originator, заголовки, URL бэкенда, имя модели) лежат в конфиг-объектах своих модулей (`BackendProfile`, `AuthConfig`), а не размазаны по коду.

## Клиент модели (`ModelGateway`)
- `POST` на эндпоинт бэкенда (для API-ключа — публичный Responses API), `stream=true`.
- Без состояния на сервере (`store=false`): каждый запрос содержит всю историю диалога.
- `instructions` — системный промпт с правилами: использовать только выданные инструменты, данные из инструментов и файлов считать недоверенными.
- Обработка SSE: дельты текста → в UI; `function_call` → в цикл инструментов; `response.completed` → конец шага; события ошибок → сообщение пользователю.
- Ошибки: 401 (refresh, потом повтор один раз), 403 (сообщение «доступ закрыт, проверьте способ входа»), 429 (пауза и понятное сообщение), обрыв сети, таймаут.
- Имя модели берётся из конфига/настроек, не хардкодится.
- Ограничение размера истории: отправлять целые ходы (связанные вызов инструмента и его результат не разрезаются, окно начинается с вопроса пользователя; самый новый ход входит всегда) или до лимита токенов, вывод инструмента обрезать до 4 КБ.

## Цикл агента (`AgentLoop`)
1. Отправить историю → получить поток.
2. Если пришёл `function_call`: проверить имя по реестру, провалидировать аргументы, при необходимости показать подтверждение, выполнить, добавить в историю `function_call` и `function_call_output` (`call_id` тот же).
3. Повторить запрос. Лимит 5 шагов за одно сообщение пользователя, потом остановка с пояснением.
4. Пользователь может нажать «Стоп»: отмена запроса и текущего инструмента.

## Инструменты
Каждый: имя, описание, JSON-схема аргументов, обработчик, флаг подтверждения, ограничение размера результата.

| Инструмент | Аргументы | Реализация | Подтверждение |
|---|---|---|---|
| `set_alarm` | `hour` 0-23, `minute` 0-59, `label?` ≤ 60 симв., `days?` | `ACTION_SET_ALARM`, `EXTRA_SKIP_UI=true` после собственного подтверждения в приложении; перед запуском `resolveActivity`. Результат: «запрос отправлен в приложение Часы» (подтверждения создания нет) | да |
| `find_files` | `query` (подстрока имени), `limit` ≤ 20 | SAF: пользователь один раз выбирает папку (`OpenDocumentTree`), `takePersistableUriPermission`; обход в ширину через `ContentResolver.query` по `DocumentsContract`; лимиты: глубина ≤ 6, ≤ 5000 просмотренных узлов, таймаут 5 с, `Dispatchers.IO`. Возвращает имя, относительный путь, размер, дату, MIME. Содержимое файлов не читается и в модель не уходит | нет (только чтение метаданных) |
| `search_files` | `query` (непустая подстрока имени, ≤ 200 символов) | MediaStore `Files` + `Downloads`, совпадение по `DISPLAY_NAME`, сортировка по `DATE_MODIFIED DESC`; максимум 20, дедупликация по точным имени и размеру, таймаут 5 с. Возвращает JSON с именем, `content://` URI, относительным путём, размером, датой и MIME. Только доступные приложению метаданные, содержимое не читается | нет (только чтение метаданных) |
| `notify` | `title` ≤ 60, `text` ≤ 200 | `NotificationManagerCompat`, канал создаётся при старте; на API 33+ сначала `POST_NOTIFICATIONS` | нет |

Правила: никакого `run_shell`, произвольных путей, чтения содержимого файлов; неизвестное имя инструмента или невалидные аргументы → ошибка модели без выполнения.

## Интерфейс
- Экран чата: сообщения, поле ввода, кнопка «Стоп», индикатор шага.
- Карточки вызова инструментов в ленте: имя, аргументы, результат.
- Шторка подтверждения: «Поставить будильник на 07:30 «Работа»?» — Разрешить / Отклонить. Текст формирует сам инструмент. Если модель просит сразу несколько действий (например, пять будильников), шторка одна: список действий и «Разрешить все» / «Отклонить все» (ADR 0004).
- Внешний вид, стиль и правила вёрстки: [design/overview.md](../design/overview.md).
- Экран настроек: способ входа и статус, выбор папки для поиска, очистка истории, выход.
- Экран входа: кнопка «Войти через OpenAI», ссылка «Использовать API-ключ».

## Разрешения и манифест
- `com.android.alarm.permission.SET_ALARM`, `POST_NOTIFICATIONS`, `INTERNET`.
- `<queries>` для `android.intent.action.SET_ALARM`.
- `find_files` работает только в папке, выбранной через SAF. `search_files` использует доступные приложению строки MediaStore и не читает содержимое. На Android 10+ такой поиск не охватывает все файлы: часть загрузок других приложений доступна только через SAF; запасной обход SAF-корней для `search_files` не выполняется. `MANAGE_EXTERNAL_STORAGE` не используется.
- Для `search_files`: `READ_EXTERNAL_STORAGE` до API 33; `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, `READ_MEDIA_AUDIO` с API 33; `READ_MEDIA_VISUAL_USER_SELECTED` с API 34 для частичного доступа к выбранным фото и видео.
- Разрешения запрашиваются в момент первого использования с объяснением.
