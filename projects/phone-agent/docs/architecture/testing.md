# Тестирование, TDD и защита архитектуры

> См. также: [ядро](core.md) · [рецепты](recipes.md)

## Тестирование и TDD

**Работаем по TDD.** Цикл на каждое поведение, маленькими шагами (минуты, а не часы):
1. **Red.** Список тест-кейсов согласуем до кода. Пишем один тест, запускаем, убеждаемся, что он падает **по нужной причине** (а не из-за ошибки компиляции).
2. **Green.** Минимальный код, чтобы тест прошёл.
3. **Refactor.** Чистим код и тесты, пока всё зелёное, поведение не меняем.

**Где TDD строгий (тест всегда первый):** ядро, `:data:llm` (по записанным образцам ответов), `:data:auth` (PKCE, JWT, refresh), чистые функции инструментов (валидация, сборка intent, лимиты обхода), ViewModel. Баг: сначала падающий тест, который его воспроизводит, потом исправление.

**Где тест первым не получится:** вёрстка Compose и тонкие Android-обёртки (`NotificationManager`, запуск intent, SAF). Логику вокруг них покрываем по TDD, обёртку проверяем instrumented-тестом или чек-листом на телефоне сразу после написания. Это осознанное исключение, а не лазейка: именно ради него обёртки держим тонкими (humble object).

**Правила тестов:**
- один тест — одно поведение; имя предложением в обратных кавычках; arrange–act–assert;
- тест проверяет поведение, а не внутренности; для портов **фейки вместо моков**;
- у фейка порта есть **контрактный тест** (`core/domain/src/testFixtures/.../contracts/`): один набор проверок гоняется и против фейка, и против настоящей реализации (примеры: `CredentialsProviderContract` для `FakeCredentialsProvider` и `SessionManager`, `ModelGatewayContract` для `FakeModelGateway` и `ResponsesGateway` на `MockWebServer`), чтобы фейк не разошёлся с настоящим; новый порт с фейком получает такой же;
- детерминизм: нет реального времени, сети и случайности (`Clock`, тестовые диспетчеры, виртуальное время);
- тест не правим, «чтобы прошёл»: если он неверен, объясняем причину и согласуем изменение;
- покрытие кода — сигнал, а не цель; пороги для `:core:domain` и `:data:auth` обсудим на этапе 1 (например, отчёт через Kover).

| Уровень | Что проверяем | Чем |
|---|---|---|
| Ядро | автомат `AgentLoop`, конвейер, политики | JUnit, корутины `runTest`, Turbine, фейки из `testFixtures` |
| Адаптер модели | разбор SSE, ошибки | `MockWebServer` + записанные образцы (`spike/sample_sse.txt`) |
| Auth | PKCE, JWT, refresh single-flight | JUnit, виртуальное время |
| Инструменты | сборка intent, валидация, лимиты обхода | JUnit на чистых функциях; instrumented-тесты на устройстве для тонких Android-обёрток |
| UI | ViewModel-логика, несколько ключевых экранов | JUnit + Turbine, Compose UI-тесты |
| Архитектура | границы модулей и пакетов | Konsist (см. ниже «Защита архитектуры автоматикой») |

Сценарии `AgentLoop` (таблично): только текст; один инструмент; инструмент упал; неизвестный инструмент; несколько вызовов в одном ответе; отказ пользователя; лимит шагов; отмена посреди потока; ошибка модели посреди потока.
Один параметризованный тест проверяет все зарегистрированные инструменты: уникальные имена, валидная схема, задан `Risk`, `describe` возвращает непустые заголовок и суть.

## Защита архитектуры автоматикой

Правила, которые обязаны быть тестами/настройками (этап 1):
1. `:core:domain` не подключает Android и сетевые библиотеки (Gradle) и не импортирует `android.*`, `androidx.*`, `okhttp3`, `dagger`, `room` (Konsist).
2. Пакеты внутри `:tools` не импортируют друг друга.
3. `ui` не импортирует реализации адаптеров (`data.*`, `tools.*`), только ядро.
4. ViewModel не хранит `Context`, `Activity`, `View`.
5. Запрещены `GlobalScope`, `runBlocking`, `Thread.sleep` в основном коде.
6. Любой класс, реализующий `Tool`, лежит в `tools.*` и называется `*Tool`.
7. Прямые `android.util.Log` запрещены, только `AppLogger` (он вырезает токены).
8. В библиотечных модулях `explicitApi()`.
9. Форматирование и стиль: ktlint/spotless, сложность: detekt, плюс Android lint. Всё запускается через `./gradlew check`.
10. Правила Compose: `compose-rules` (mrmans0n) в ktlint или detekt.
11. Литералы цвета `Color(0x…)` только в `ui/designsystem/theme`; `designsystem` не импортирует экраны.
12. Нет строковых литералов в `Text("…")` в `ui/**` (все тексты в `strings.xml`); возможность проверки Konsist подтверждаем на этапе 1.
13. Markdown-библиотека используется только внутри `AssistantMarkdown`; модуль загрузки картинок (`-coil3`) не подключается.
