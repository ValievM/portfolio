# Решения и риски архитектуры

> См. также: [обзор](overview.md) · [решения по дизайну](../design/qa.md)

## Ключевые решения и альтернативы

| Решение | Альтернативы | Почему так |
|---|---|---|
| Нативный Kotlin + Compose | Flutter | инструменты — Android API, меньше слоёв и памяти |
| Hexagonal-ядро, без полного DDD | Clean+DDD целиком | одиночный MVP, домен небольшой |
| 5 модулей, рост по триггерам | один модуль / 15 модулей | Google предупреждает о обеих крайностях |
| Hilt | Koin, ручной DI | рекомендация Google, ошибки связывания видны при сборке |
| OkHttp напрямую | Retrofit, Ktor | один эндпоинт + SSE |
| kotlinx.serialization | Moshi, Gson | Kotlin-native, работает в чистой JVM, подходит для схем |
| Flow для агента | callbacks, Rx | отмена и композиция «из коробки» |
| Ошибки как sealed-типы | исключения | явные пути, проще тестировать |
| Инструменты через multibinding | `when(name)` в цикле | расширение без правки цикла |
| KMP не сейчас | KMP сразу | ядро чистый Kotlin, дверь остаётся открытой (OkHttp тогда заменить на Ktor) |

## Риски архитектуры и открытые вопросы
- **`UserInteractionBridge`** — самое тонкое место (жизненный цикл Activity, отмены). Делаем и тестируем отдельно на этапе 4.
- **Hilt в библиотечных модулях** добавляет настройку; если станет обузой, регистрацию инструментов переносим в `:app`.
- **Нужен ли `Opaque`-слот** и как бэкенд ведёт себя при `store=false`: проверяет этап 0.
- Открыто: имя и пакет приложения; список включаемых инструментов в настройках (MVP или позже). Внешний вид решён («Стык», [ADR 0006](../adr/0006-brand-joint.md)); открытое по нему в [design/qa.md](../design/qa.md). Навигация решена: Navigation 3.
