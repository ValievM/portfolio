# Проверка интерфейса и решения по дизайну

> См. также: [правила вёрстки](layout-rules.md) · [библиотеки](libraries.md) · [тесты и TDD](../architecture/testing.md)

## Тестирование интерфейса (совместимо с TDD)
1. **Логика первым:** состояния и поведение (`ChatUiState`, «прилипание» к низу, показ шторки) тестируем на уровне ViewModel и чистых функций до вёрстки.
2. **Вёрстка потом:** превью состояний, затем скриншот-тесты (Roborazzi) для `Composer`, `ToolCallCard` (все состояния), `ApprovalSheet`, `AssistantMessage` с markdown. Эталонные снимки записываем, когда дизайн утверждён.
3. **Семантика:** проверки `contentDescription`, ролей, порядка фокуса для ключевых экранов.
4. **Как запускать скриншот-тесты** (Roborazzi + Robolectric, `app/src/test/kotlin/.../screenshot/`):
   - `./gradlew check` — тесты идут как обычные: каждый компонент отрисовывается в светлой и тёмной темах (и при шрифте 2.0), но картинки не пишутся и не сравниваются. Это дымовая проверка, что вёрстка не падает.
   - `./gradlew :app:recordRoborazziDebug` — записать снимки в `app/src/test/screenshots/`.
   - `./gradlew :app:verifyRoborazziDebug` — сравнить с эталонами, упасть при отличиях; `compareRoborazziDebug` — отчёт с diff.
   - **Эталоны пока не закоммичены**: дизайн ещё не утверждён, `app/src/test/screenshots/` в `.gitignore`. Когда пользователь утвердит вид: убрать строку из `.gitignore`, записать снимки, закоммитить, добавить `verifyRoborazziDebug` в проверки.
   - Размеры: `NarrowPhoneScreenshotTest` (320dp), `TabletScreenshotTest` (840dp), `LandscapePhoneScreenshotTest` (800x360dp) рисуют чат, пустой чат и вход; экраны входа, настроек, корня и шторки при шрифте 200% в `ScreensScreenshotTest` и `*ScreenshotTest`.
   - Поведение размеров держат обычные тесты: `SheetsAdaptiveUiTest` (кнопки шторок достижимы при 15 пунктах, шрифте 200% и 320dp), `ContentColumnUiTest` (колонка 640dp по центру).
   - Новый компонент или состояние: тест в `screenshot/` через `composeRule.snapshot("имя") { … }` (варианты Light/Dark/LargeFont, `fillScreen` для экранов, `wholeScreen` для шторок и диалогов).
5. **Статика:** Konsist-правила (цвета-литералы только в теме, `designsystem` не импортирует экраны, нет строковых литералов в `Text(...)` **[проверить возможность]**) и `compose-rules`.

**Чек-лист Design QA (для каждого экрана):**
- [ ] светлая и тёмная темы; динамические цвета включены и выключены;
- [ ] масштаб шрифта 1.0 / 1.3 / 2.0;
- [ ] узкий экран (320dp), обычный, широкий (планшет: контент не шире 640dp), ландшафт;
- [ ] клавиатура открыта: композер виден, последнее сообщение не перекрыто;
- [ ] длинные русские слова и очень длинное сообщение, длинные аргументы инструмента;
- [ ] состояния: пусто, загрузка, ошибка, нет сети, сессия истекла;
- [ ] TalkBack: порядок чтения, подписи, объявление статуса ответа;
- [ ] жест «назад» (predictive back) на всех экранах и в шторке;
- [ ] «Убрать анимации» в системных настройках.

## Решения и открытые вопросы

| Решение | Альтернативы | Почему |
|---|---|---|
| M3 стабильный | Expressive alpha | продакшен без альфа-зависимостей |
| Dynamic color + запасная палитра | только своя палитра | нативность, меньше работы, пользователь может отключить |
| Вшитые variable-шрифты | Google Fonts online | офлайн, приватность, variable-оси |
| Иконки vector drawable | библиотека иконок | ~20 штук, ноль зависимостей |
| Шторка подтверждения | диалог, карточка в ленте | нельзя пропустить, легко закрыть жестом «назад» |
| Ответ ассистента без пузыря | пузыри для обоих | длинные markdown-ответы читаются лучше на всю ширину |
| Markdown-библиотека за обёрткой | своя реализация | экономия времени, замена в одном месте |
