# Доступность и безопасность интерфейса

> См. также: [правила вёрстки](layout-rules.md) · [компоненты](components.md)

## Доступность
- Область нажатия ≥ 48dp; контраст текста ≥ 4.5:1, крупного текста и элементов интерфейса ≥ 3:1 (роли M3 это обеспечивают, самодельные цвета проверяем).
- Масштаб шрифта до 200% без обрезки и наложений.
- TalkBack: у каждого сообщения роль в описании («Вы:», «Ассистент:»); статус ответа объявляется **один раз** (`liveRegion = Polite` на узле статуса «Ассистент отвечает…» → «Ответ готов»), а не по токенам.
- Статус карточки — иконка + текст, не только цвет.
- Шторка подтверждения: фокус на заголовке, «Отклонить» не хуже «Разрешить» по доступности; закрытие жестом «назад» = отклонение.
- Заголовки экранов и секций помечены `heading()`.

## Безопасность в интерфейсе
Ответ модели, вывод инструментов, имена файлов — **недоверенный текст**.
- **Картинки из markdown не загружаем** (модуль `-coil3` не подключаем): это известный канал утечки данных через URL картинки.
- Ссылки открываются только после нажатия и подтверждения с показом реального домена; схемы кроме `https` блокируем.
- HTML не рендерим (тег отбрасывается, текст остаётся обычным, не кликабельным).
- Адрес картинки может остаться в ответе обычным неактивным текстом: он не загружается и не является ссылкой (тест `AssistantMarkdownUiTest`).
- **Шторка подтверждения рисуется из структурированных данных** (`describe(args)`), а не из текста модели: модель не может нарисовать поддельное «подтверждение» внутри ответа. Шторка пачки (`BatchApprovalSheet`) так же строится из `describe(args)` каждого вызова, показывает их все и не подтверждает то, чего в списке нет.
- Токены и секреты нигде не показываем и не пишем в превью и тестовые данные.
