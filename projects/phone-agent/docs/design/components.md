# Токены, компоненты, экраны

> См. также: [стиль](style.md) · [правила вёрстки](layout-rules.md) · [CallDescription в ядре](../architecture/core.md)

## Токены

| Токен | Значения |
|---|---|
| Сетка | 4dp |
| `spacing` | `extraSmall 4`, `small 8`, `compact 12`, `medium 16`, `large 24`, `extraLarge 32` (dp) |
| Поля экрана | 16dp по бокам |
| Между сообщениями | 16dp; между текстом и карточкой 8dp; абзацы в markdown 8dp |
| Внутренние отступы | сообщение пользователя 12dp × 16dp; карточка 12dp |
| Минимальная область нажатия | 48dp |
| Иконка | 24dp (20dp в плотных местах) |
| Композер | минимальная высота 56dp, до 6 строк, потом внутренний скролл |
| Ширина контента на широких экранах | не больше 640dp, по центру |
| Длительности | 150 / 250 / 400 мс |

Реализация: `AppTheme { }` оборачивает `MaterialTheme` (цвета, типографика, формы) и добавляет `LocalSpacing` (`AppTheme.spacing.m`) и `LocalExtendedColors`. Использование `dp`-литералов для отступов вне токенов — исключение, а не норма.

## Каталог компонентов

Общее правило: **если Material 3 умеет, берём Material 3.** Свои компоненты создаём только для того, чего в M3 нет (карточка вызова, композер, сообщение), и кладём в `ui/designsystem/components`.

| Компонент | Назначение | Состояния |
|---|---|---|
| `MessageList` | лента сообщений | пусто, обычная, идёт стриминг, ошибка |
| `UserMessage` | сообщение пользователя | обычное; долгое нажатие: копировать |
| `AssistantMessage` | ответ модели (markdown) | ожидание первого токена, идёт стриминг, готово, прервано, ошибка |
| `AssistantMarkdown` | единственная обёртка над markdown-библиотекой | картинки выключены, ссылки только через подтверждение, недозакрытый код не ломает вёрстку |
| `ToolCallCard` | вызов инструмента в ленте | ожидает подтверждения, выполняется, готово, ошибка, отклонено, прервано |
| `ApprovalSheet` | шторка подтверждения | обычная, с раскрытыми подробностями |
| `Composer` | ввод | пусто, набор текста, отправка/идёт ответ (кнопка «стоп»), недоступно (нет сети, нет входа) |
| `StatusBanner` | системные сообщения над композером | нет сети, сессия истекла (с кнопкой «Войти заново») |
| `EmptyState` | пустой чат | заголовок + 3 подсказки-чипа (нажатие подставляет текст, **не отправляет**) |
| `ScrollToBottomChip` | «↓ к новым» | виден, только если пользователь прокрутил вверх |
| `InlineError`, `StatusBanner` | ошибка в ленте, системное сообщение над панелью ввода | иконка, весь текст, «Повторить», закрыть; появление 160 мс |
| `StatusMessage` | неснимаемое сообщение внутри экрана (вход, настройки) | ошибка, предупреждение |
| `PreparingIndicator` | «Готовлю ответ» в ленте, пока модель готовит текст | анимация 1200 мс или неподвижный знак |
| `PrimaryButton`, `SecondaryButton`, `QuietButton`, `ButtonPair` | кнопки 16dp, минимум 48dp; пара встаёт столбиком, если не помещается | |
| `SheetLayout`, `ConfirmationSheet` | общий каркас шторок: заголовок, прокручиваемое тело, закреплённый низ; шторка всегда раскрыта по содержимому | |

**Состояния `ToolCallCard`:** плашка «иконка + слова» на роли статуса, таблица в [brand.md](brand.md#статусы-инструмента). Тексты: «Нужно подтверждение», «Выполняется», результат инструмента, причина ошибки, «Отклонено», «Прервано». Смена статуса перекрёстно затухает за 120 мс.

Карточка по умолчанию свёрнута: человеческое название + суть в одну строку. Раскрытие показывает аргументы моноширинным шрифтом. Название и суть формирует **сам инструмент** (метод `describe(args)` в порте `Tool`), поэтому новый инструмент получает нормальную карточку и текст подтверждения без правки UI.

## Экраны

**Чат (главный):**
```
┌──────────────────────────────────┐
│  Название приложения           ⚙ │  верхняя панель, одна иконка
├──────────────────────────────────┤
│                    ┌────────────┐│
│                    │ Поставь    ││  сообщение пользователя
│                    │ будильник  ││  (справа, тональный фон)
│                    │ на 7:30    ││
│                    └────────────┘│
│ Ставлю будильник на 07:30.       │  ответ ассистента: без пузыря,
│ ┌──────────────────────────────┐ │  на всю ширину
│ │ ⏰ Будильник             ✓  ⌄ │ │  карточка вызова (свёрнута)
│ │ 07:30 · «Работа»             │ │
│ └──────────────────────────────┘ │
│ Готово. Проверьте в приложении   │
│ «Часы».                          │
│                     [ ↓ к новым ]│  только при прокрутке вверх
├──────────────────────────────────┤
│ ┌──────────────────────────┐ ┌──┐│
│ │ Сообщение                │ │ ↑││  композер; ↑ превращается в ■
│ └──────────────────────────┘ └──┘│
└──────────────────────────────────┘
```

**Шторка подтверждения** (поверх чата, композер недоступен, «назад» = «Отклонить»):
```
│ ────                             │
│ Разрешить действие?              │
│ ⏰ Поставить будильник            │
│ 07:30 · «Работа»                 │
│ Подробности ⌄                    │  раскрывает аргументы (моно)
│ [   Отклонить   ] [ Разрешить  ] │  «Разрешить» не в фокусе по умолчанию
```

**Вход:** логотип, заголовок, основная кнопка «Войти через OpenAI», вторичная «Использовать API-ключ», мелким текстом: «Токены хранятся только на этом устройстве».
**Настройки:** список секций «Вход» (способ и статус, «Выйти»), «Поиск файлов» (выбранная папка), «Модель», «Оформление» (цвета системы), «О приложении».
Пустой чат (`EmptyState`): три подсказки, например «Поставь будильник на 7:30», «Найди файл…», «Покажи уведомление…».
