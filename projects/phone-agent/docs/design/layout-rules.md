# Правила вёрстки (Compose)

> См. также: [компоненты](components.md) · [доступность и безопасность](a11y-security.md) · [UI-архитектура](../architecture/ui.md)

**Структура и окна**
- Edge-to-edge (`enableEdgeToEdge()`), системные отступы через `Scaffold` и `WindowInsets`. Не добавлять отступы вручную под статус-бар.
- Клавиатура: `imePadding()` только у композера, `imeNestedScroll()` у списка. Список получает нижний отступ, равный высоте композера, чтобы поле не перекрывало последнее сообщение.
- Широкие экраны: контент не шире 640dp, по центру через `Modifier.contentColumn()`. Порядок в нём важен: `widthIn(max)` после `fillMaxWidth()` не срабатывает (ограничение уже зафиксировано), поэтому не писать эту пару руками. Планшетная раскладка не в MVP.
- Поля экрана `screenMargin()` (20dp, 16dp уже 360dp). Списки прокручиваются под системными панелями: отступы окна отдаём в `contentPadding`, не в рамку вокруг списка. Нижний край и клавиатура: `Composer` сам (`navigationBars` + `imePadding`), поэтому `Scaffold` чата не берёт нижний отступ.
- Пара действий: `ButtonPair` (рядом, если помещается, иначе столбиком, главная сверху). Шторки подтверждения через `SheetLayout` и `ConfirmationSheet`: без «полуоткрытого» состояния (в нём кнопки могли оказаться за краем экрана), тело прокручивается, кнопки закреплены.
- Ландшафт должен работать: композер и контент читаемы.

**Composable-функции**
- Экран = `XRoute` (берёт ViewModel) + `XScreen(state, onEvent, modifier)` (без логики). ViewModel вглубь не передаём.
- Первый необязательный параметр: `modifier: Modifier = Modifier`; применяется к корневому элементу.
- Состояние поднимаем вверх (state hoisting). Черновик текста: `rememberSaveable`.
- Слоты (`content: @Composable () -> Unit`) вместо флагов-режимов.
- Если Material 3 умеет, не оборачиваем; собственные компоненты называем по смыслу (`ToolCallCard`). Исключение: кнопки (`PrimaryButton`, `SecondaryButton`, `QuietButton`), потому что в M3 нет роли формы кнопки.
- Файл больше ~300 строк — повод разделить.

**Ресурсы: никакого хардкода**
- Цвета только из `MaterialTheme.colorScheme` и `AppTheme.extendedColors`. Литералы `Color(0x…)` разрешены только в `ui/designsystem/theme`.
- Отступы из `AppTheme.spacing`.
- Строки из `stringResource`, `pluralStringResource`. Литералы в `Text("…")` запрещены.
- Иконки только через `AppIcons`.

**Списки и стриминг**
- `LazyColumn` с `key` (id сообщения) и `contentType`. Решение: `reverseLayout = true` (новые внизу, при росте последнего сообщения список не «прыгает»); **[проверить, этап 3]** порядок обхода TalkBack; запасной вариант: обычный порядок + логика «прилипания» к низу.
- Автопрокрутка вниз **только если** пользователь уже внизу; иначе показываем `ScrollToBottomChip`. Логика «прилипания» — чистая функция, тестируется по TDD.
- Стриминг: UI обновляем пачками (не на каждый токен), markdown разбирается инкрементально (`rememberStreamingMarkdownState`). Перерисовывается только последнее сообщение.
- Модели UI неизменяемые. Опираемся на strong skipping mode компилятора Compose **[проверить, этап 1]**; `@Immutable`/`@Stable` и библиотеки immutable-коллекций добавляем только если отчёты компилятора покажут проблему.
- Текст ассистента выделяемый (`SelectionContainer` на сообщение), кнопка «Копировать».

**Плавность**
- Элементы ленты `Modifier.animateItem()`; длительности и кривые только из `AppMotion`; анимации подчиняются «Убрать анимации» (масштаб 0: неподвижно, не ускоренный цикл). Постоянная анимация читает значение в фазе рисования (лямбда), а не пересоздаёт экран.
- Смена темы не пересоздаёт `NavHost`, `ViewModel` и активный ход: без `key(тема)`; цвета переходят плавно (`AnimatedColors.kt`).

**Запрещено**
- вложенные вертикальные скроллы; отступы «на глаз» вместо insets; `Dialog` для подтверждения действий; `if (isDark)` в экранах; фиксированная высота текстовых контейнеров; информация только цветом.

**Превью и состояния**
- На каждый экран и компонент: превью всех состояний (пусто, обычное, загрузка, ошибка, длинный текст) через `@PreviewLightDark` и `@PreviewFontScale`. Данные для превью берутся из фейковых `UiState`, не из сети.
- Превью — живой каталог компонентов, отдельный «каталог-экран» не создаём.
